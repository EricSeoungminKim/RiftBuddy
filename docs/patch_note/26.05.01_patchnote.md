# 26.05.01 Patch Note

> Current status note: this patch note captures the 2026-05-01 state. The latest 2026-05-02 patch supersedes the test count and LCU draft details with `62 passed`, quiet `/lcu/champ-select/status` polling, and cell-aware draft slot sync.

## Backend

- Added Groq and Gemini LLM provider support.
- Added mock LLM mode for free/local testing.
- Added richer Riot Live Client context:
  - champion name
  - localized in-game champion names from current `allPlayers`
  - ally/enemy/current-game champion lists
  - summoner name
  - game mode
  - assigned/current position mapped to Korean LoL terms
  - CS
  - KDA
  - ward score
  - items
  - summoner spells
  - recent events
  - estimated ally/enemy team gold and gold difference
- Improved Riot Live Client reliability by disabling proxy env usage for localhost polling.
- Added configurable ElevenLabs model ID.
- Added safer TTS error handling so text advice still appears when voice output fails.
- Added local auth bypass flag for real-service testing without Supabase login.
- Added Korean LoL-term response prompting and post-processing:
  - preserves Korean server terms like `탑`, `정글`, `미드`, `바텀`, `서폿`, `CS`, `KDA`, `AP`, `AD`, `CC`
  - normalizes `bottom lane`, `jungle`, `middle lane`, `support` into Korean LoL terms
  - removes Chinese/Japanese/broken characters and random English fragments
- Added optional wake word pipeline:
  - English wake phrase detection.
  - Korean question transcription after wake.
  - Siri-style flow: wake -> "네?" -> listen until silence -> answer -> return to standby.
- Disabled wake word for the current local-first interaction model; voice questions now use a hotkey instead of always-on listening.
- Split STT settings for wake detection and question recognition:
  - wake model/language
  - question model/language
- Switched STT from `faster-whisper` to OpenAI `openai-whisper`.
- Added Korean LoL-term `initial_prompt` for question transcription.
- Added silence detection settings for post-wake question capture.
- Added hotkey voice-question recording improvements:
  - 0.5s preparation delay
  - "Buddy가 듣고 있습니다..." recording status
  - minimum 2s recording window
  - transcript cleanup and bad-transcript rejection
- Added active WebSocket client tracking so wake-word results can be broadcast to the overlay.
- Added transcript/listening events so the UI can show when the assistant heard the wake word and when it is waiting for the user's question.
- Added rule-based planned question generation for `Command/Ctrl + Shift + B`.
  - low health + high gold asks about recall timing
  - winning/losing estimated team gold asks about closing or comeback plans
  - jungle + healthy + low gold asks about jungle route/gank/objective priority

## Frontend / Electron

- Added Electron overlay mode:
  - transparent window
  - always-on-top
  - click-through
  - visible over the League client
- Added global hotkeys:
  - `Command/Ctrl + Shift + B` requests planned context-aware advice while League has focus.
  - `Command/Ctrl + Shift + Space` starts a custom voice question.
  - `Command/Ctrl + Shift + L` toggles English/Korean mode.
- Added chat-style overlay messages:
  - `USER: ...`
  - `Buddy: ...`
- Added listening feedback for voice-question mode:
  - `Buddy: 준비하세요. 곧 말하면 됩니다...`
  - `Buddy: Buddy가 듣고 있습니다...`
- Added auto-scroll and taller overlay chat panel.
- Added frontend root `.env` loading through Vite config.
- Added default root `.env` WebSocket support for `VITE_RIFTBUDDY_WS_URL`.
- Changed frontend advice hotkey from a fixed prompt to backend-planned mode: `{ mode: "planned", query: null }`.
